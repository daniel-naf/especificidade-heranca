Conceito · Herança

Herança: o valor desce pela árvore

Herança é o mecanismo pelo qual determinados valores de propriedades CSS passam de um elemento ancestral para seus descendentes — quando nenhuma regra específica sobrescreve aquele valor.

↓Sempre de cima para baixo: o filho nunca passa valor para o pai.
↓Quem tem valor próprio usa o seu — e passa esse adiante.

Clique em um elemento para declarar color nele

Clique no <p> e pergunte: "o que acontece com o span? e com a div?"
  • Estado inicial: só o body declara color. Todos abaixo herdam (linha verde).
  • Clique no <p>: ele ganha cor própria; o span passa a herdar do p; a div continua herdando do body.
  • Clique de novo no mesmo elemento para trocar a cor ou remover a declaração.
  • Frase para fixar: "o filho herda do ancestral mais próximo que tem um valor".

Regra prática

Texto costuma herdar. Caixa, não.

Geralmente herdadas

Propriedades de texto: faz sentido o conteúdo inteiro seguir o mesmo estilo.

text-alignletter-spacinglist-stylevisibilitycursor

Geralmente não herdadas

Propriedades da caixa e do layout: cada elemento tem a sua.

marginpaddingborderwidthheightbackground

Não herdou e ninguém definiu? Vale o valor inicial da propriedade: margin: 0, border: none…

A herança depende da propriedade. CSS não significa que tudo passa do pai para o filho — e a lista não é para decorar: na dúvida, teste ou consulte a documentação.
"Mas o fundo do filho fica igual ao do pai!" Parece herança, mas não é: o background inicial do filho é transparente, então o fundo do pai aparece através dele.

  • As etiquetas cinzas são "e também" — só para mostrar que a lista é maior.
  • O caso do background costuma gerar dúvida real: vale 20 segundos.

Controle explícito · você decide

Quatro palavras para mandar na herança

O que colocar no ?

Mesma situação, quatro respostas. Clique em cada palavra e peça para preverem o link.
  • Situação: o site pinta todo link de vermelho-carmim com borda. Dentro do card verde tracejado, queremos outro comportamento.
  • inherit: copia do pai — até a borda, que normalmente não herda.
  • initial: valor "de fábrica" da especificação (color preto, sem borda). Não é o padrão do navegador.
  • unset: age como inherit em color (herdável) e como initial em border (não herdável).
  • revert: desfaz o CSS do site e devolve o link azul padrão do navegador.
  • Clique de novo na palavra selecionada para voltar ao estado sem regra.

Como comparar dois placares

Da esquerda para a direita, igual a quadro de medalhas 🥇🥈🥉: primeiro A. Empatou? Olhe B. Empatou? Olhe C.

1-0-0  vence  0-9-9

O que não conta ponto

O seletor universal * e os combinadores: espaço, >, + e ~.

Eles mudam quem é selecionado, não a força da regra.

  • Cada seletor ganha um placar de três números. Conta-se quantos IDs, quantas classes (e parentes) e quantos elementos ele tem.
  • Analogia do quadro de medalhas: 1 ouro vale mais que 9 pratas e 9 bronzes.
  • Pergunta rápida: "div > p vale mais que div p?" Não — o > não conta. Os dois são 0-0-2.

Bônus · para os curiosos

Seis casos que parecem uma coisa e valem outra

O seletor universal não soma nada.

É seletor de atributo: vale como classe. Já #titulo vale 1-0-0.

Repetir a classe aumenta a força. Funciona — mas é gambiarra.

:where() vale sempre zero, não importa o que tem dentro.

:is() assume o argumento mais específico da lista.

O :not() em si não soma. O argumento dele, sim.

Para levar: o placar olha o tipo de cada pedaço do seletor, não o que ele acaba selecionando. [id="titulo"] e #titulo pegam o mesmo elemento com forças diferentes.
  • Slide opcional. Se o relógio estiver apertado, passe direto.
  • Se usar: cubra o placar com a mão e pergunte "quanto vale?" em dois ou três cards.
  • Este conteúdo não entra no quiz final.

Prioridade · !important

!important: a declaração que fura a fila

Clique nos !important para ligar e desligar.
Liga 1 · declarações !important

Disputam primeiro. Se houver mais de uma, volta a valer a especificidade e, depois, a ordem.

Liga 2 · declarações normais

Só decidem se a liga 1 estiver vazia: inline › placar A-B-C › ordem.

Roteiro: desligue o !important do p → religue → ligue também no #titulo → ligue o inline.
  • Estado inicial: p { color: red !important } vence o ID. Uma declaração !important ganha de qualquer declaração normal.
  • Desligue o !important do p: volta a valer o placar, e #titulo (1-0-0) vence.
  • Ligue !important nos dois: entre importantes, a especificidade decide de novo — azul.
  • Ligue o inline: sem nenhum !important, ele vence todos. Com !important em alguma regra, o inline normal perde.
  • Por isso não é "o maior número": ele muda a declaração de liga.
Cuidado

⚠️ Não use !important como solução padrão

A guerra do !important, em 4 capítulos

1
.btn { color: blue; }
Não funcionou: alguma regra mais forte está vencendo.
2
.btn { color: blue !important; }
"Resolvido!" — sem descobrir quem estava vencendo.
3
.btn-perigo { color: red !important; }
Semanas depois, um botão precisa ser vermelho. Agora só outro !important vence.
4
#form .btn-perigo { color: red !important; }
E depois, !important com mais especificidade. A escalada não tem fim.

Antes de usar, tente nesta ordem

  • Conferir se o seletor acerta mesmo o elemento.
  • Descobrir qual regra está vencendo — e por quê.
  • Ajustar a especificidade com critério.
  • Reorganizar a ordem das regras.

Quando ele faz sentido

Em classes utilitárias que precisam valer sempre, como .oculto { display: none !important; }, ou para sobrescrever CSS de terceiros que você não pode editar.

  • Conte como história: cada !important obriga o próximo conflito a usar outro.
  • Mensagem central: !important esconde o problema em vez de resolver. O CSS fica difícil de manter.
  • A lista da direita é um ensaio do checklist de debugging que vem daqui a pouco.

O botão está dentro do formulário e tem a classe .btn-danger. Qual fundo aparece?

color ↓ herda

Tudo o que vimos, em uma tela

herança
Valores descem do ancestral para os descendentes.
herda × não herda
Texto costuma herdar; caixa, não. Depende da propriedade.
inherit
Pegue o valor do pai, mesmo que a propriedade não herde.
initial
Valor inicial da especificação — não o do navegador.
unset
inherit se a propriedade herda; initial se não herda.
revert
Desfaz o CSS do autor: volta o padrão do navegador.
especificidade
A força do seletor, no placar A-B-C.
comparar seletores
Da esquerda para a direita: A, depois B, depois C.
empate
Placar igual dos dois lados: a especificidade não decide.
ordem da declaração
No empate, a regra que aparece depois vence.
!important
Fura a fila das declarações normais. Use com parcimônia.
cascata
O processo inteiro que escolhe o valor final.
